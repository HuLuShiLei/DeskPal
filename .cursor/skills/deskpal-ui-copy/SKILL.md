# DeskPal 界面文案

现有文案在 2026-11-13 中英文整体润色过（提交 `style: 润色中英文界面文案` 及之后几次）。**新文案照着现有文案的样子写，不要回头改已有文案。**只有用户明确点名某一句时才改那一句。

文案位置：C# 生成的在 `DeskPal.Client.Core/Localization/Strings.resx`（中文）和 `Strings.en.resx`；页面自己的在 `web/src/i18n/zh-CN.ts` 和 `en.ts`。两种语言同时写，键名相同。

## 写之前

1. 先在两份字典里搜一遍，看有没有意思相同的现成文案（`common.*`、「已保存」「已清除」「无法连接服务器」等），能复用就复用，不要再写一句近义的。
2. 找同类控件的现有文案对照着写：设置行看 `settings.*`、`usage.*`；确认对话框看 `room.leave*`、`room.block*`、`usage.clear*`；开关的说明看 `sharing.*`、`privacy.share*`。

## 总体语气

正式桌面软件的书面用语，像系统设置或常见国产桌面软件，不像聊天，也不像 AI 回答。

- 短。标签用名词短语；说明一到两句，只写「会发生什么」「有什么后果」，不解释设计原因。
- 不用口头语和客套：不用「哦」「啦」「呢」「轻松」「帮你」「放心」「随时」「一键」「贴心」，不用感叹号、表情符号。
- 「请」只用在必须由用户做的一步上（「请重新登录」「请先导出」「请勿发给他人」），不要每句加。
- 称呼用「你」。`usage.note`（「数据仅保存至本地。传输时服务器将加密转发，您的数据不会保存至服务器。」）是用户亲自定的原句，保留「您」，不要统一。
- 不夸大安全性：Server 能看到的东西不写「加密」「安全」；做不到端到端加密就不说端到端。

## 用词

| 用 | 不用 |
|---|---|
| 房间、房间成员、该房间、此房间 | Room、群、频道 |
| 服务器 | Server、云端、后台 |
| 本机、这台电脑、其他电脑 | 设备、终端、PC |
| 使用统计 | 数据统计、时长记录 |
| 工作中、在聊天、正在浏览网页、正在使用 XX、在看视频、在玩游戏、暂离 | 忙、摸鱼、上班、闲着 |
| 所有者、踢出、屏蔽、暂停分享、纠正分类、公开使用统计 | 房主、群主、移除成员、拉黑 |
| 显示名称、修改名称 | 昵称、改名 |
| 开启 / 关闭（功能）、打开（页面、链接） | 启用 / 禁用、跳转 |

英文对应：room, members, server, this computer, usage stats, owner, kick, block, Pause sharing。不要自造缩写和简称。

## 标点和格式

中文：

- 全角标点。名称、按钮名、页面名用「」：「{name}的房间」「在「设置」中关闭」。
- 中文和数字、英文之间留一个空格：「最近 7 天」「1 到 30 个字符」「100 MB」「Windows 后」。百分号、单位符号贴着数字。
- 完整的句子（说明、对话框正文、错误、提示条）以句号结尾；短标签、按钮、单行的设置说明（「登录 Windows 后在后台启动」）不加句号。
- 进行中的提示用「正在……」加省略号「…」：「正在检查更新…」。
- 多条内容用 `\n\n` 分段，列表用「· 」开头（见 `sharing.message`）。

英文：

- Sentence case：只有首字母和专有名词大写（「Keep details for」，不是「Keep Details For」）。
- 按钮和菜单用动词开头，不加句号；说明和对话框正文用完整句子，加句号。
- 用缩写 don't、can't；不用 please，除非中文原句也用了「请」。
- 天数等数量用已经格式化好的「7 days / 1 day」（`PresenceFormatter.Days`），模板里不要再写 days。

## 各类控件

| 控件 | 中文写法 | 例子 |
|---|---|---|
| 设置行标题 | 名词短语，2 到 6 个字 | 保留时长、导入导出、开机自启 |
| 设置行说明（`hint`） | 一句，写效果或范围 | 「面板保持在其他窗口之上」 |
| 开关打开后的提示 | 「已开启」，必要时加去哪里关 | 「已开启，可在设置中关闭」 |
| 关闭后会删数据的开关 | 关闭提示直接写删除了什么 | 「已关闭。已上传的未识别应用记录将被删除」 |
| 确认对话框标题 | 动作 + 对象，和触发按钮一致 | 清除全部统计、退出房间、屏蔽成员 |
| 确认对话框正文 | 先写后果，再写例外和怎么挽回；不可逆写「且无法恢复」 | 「将删除本机上此账号的全部使用统计和查看记录，且无法恢复。如需保留，请先导出。」 |
| 确认按钮 | 单个动词，和标题动作一致；删除类设 `danger` | 清除、退出、解散、屏蔽 |
| 完成提示（toast） | 「已」+ 动词 | 已保存、已清除、已退出 |
| 错误 | 一句说清哪里不行，可操作时加怎么办；不带地址、异常信息、HTTP 细节 | 「无法连接服务器，请检查网络后重试」 |
| 空状态 | 「还没有……」或「尚无……」，可接一句去哪里添加 | 「尚无查看记录」 |

涉及隐私换便利的开关（上传、公开、同步）：开启前弹确认对话框，正文按顺序写清 ①会上传或公开什么（点名窗口标题、网页标题这类敏感项）②谁能看到（房间成员 / 服务器）③关闭后怎样（是否立即删除）。按钮写动作本身（「公开」「开启同步」），不写「同意」「确定」。

## 英文长度

界面按中文设计，英文通常更长。最小窗口 400×480 下不能折行或横向溢出：

- 导航只放一个词（Status、Stats、Rooms、Rules、Settings）。
- 设置行标题在 400px 下只有约 100px 宽，超过就缩短（「Import and export」改成了「Transfer」）。
- 单选、下拉选项、按钮要短（「Include titles」「Minimize to tray」）。
- 说明文字可以换行，但不要写成三句以上。

写完用 `npm run dev` 打开 `?mock=<样例>&lang=en`，在 Cursor 自带浏览器里把视口设为 400 宽看一遍（见 rule `wpf-ui`）。

## 已定稿，不要改

- 状态用语：工作中、在聊天、正在浏览网页、正在使用 XX、在看视频、在玩游戏、暂离。
- 无房间提示：「当前无房间。请创建或选择一个房间，也可以用邀请码加入。」
- `usage.note` 中英文（用户指定原句和译法）。
- 已有的所有键。新功能需要不同说法时新增键，不要改旧键的值；旧文案和新功能冲突时（例如原句说「不会保存至服务器」，新功能会保存），新增一句在对应条件下替换显示，并在回复里告诉用户。

## CHANGELOG 条目

同样书面中文，写用户能感觉到的变化，不写类名、接口、提交号。一条一句，以句号结尾；下一行缩进 `en:` 写英文。格式和版本号规则见 `AGENTS.md`。

## 改完检查

- 两份字典键一致：`npm run build`（英文少键会失败），`dotnet test`（`LocalizationTests` 检查 resx）。
