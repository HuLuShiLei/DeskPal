# 分类规则和使用统计调整

2026-11-16 用户周末试用后提出的 6 个问题。本文件是阶段 0 的 plan，用户确认前不改业务代码。2026-11-16 已确认的口径见「已定」。第 4、6 条是调研，结论写在「周末数据」和「分类调整」两节。

## 这次做什么

1. 统计「按状态」不再出现「放松」，视频和游戏分开显示。
2. 统计里可以更改某个应用或网站的分类，历史数据按新分类重新统计；开启同步时，其他电脑看到的结果也一致。
3. 统计查看今天时，不再显示「昨天全天 x」。
4. 重新梳理分类：浏览器里看视频要能识别为视频；PotPlayer、B 站全屏播放的问题。
5. FINAL FANTASY XIV 被识别为视频。
6. 根据周末数据检查规则和分类的问题（和第 4 条合并）。
7. 跟随账号的设置分两种：「不记录标题」和「详细记录保留时长」只在开启「同步到服务器」时用 PIN 码加密同步；「暂离」时长可以在设置里选择，登录后按账号同步（明文）。

不做：房间成员实时状态的协议不变（`Envelope`、`PresenceSnapshot` 不加字段）；不新增类别（仍是工作、聊天、视频、游戏、浏览网页、其他）；不做浏览器扩展。夜间模式、语言、关闭窗口、置顶、测试版、当前房间仍只在本机。

## 改动方案

### 第 1 条：只显示状态时显示六种之一，去掉「放松」

- `PrivacyFilter.Apply`：`StateOnly` 保留类别，只去掉应用名和详情。不改协议：`PresenceSnapshot` 本来就有 `Category`，旧版本客户端收到后按 `SlackingLabel` 显示「在看视频」「在玩游戏」。
- `PresenceFormatter`：`Slacking` 没有类别时（只会来自旧版本客户端）仍显示「在放松」，新版本不再产生。
- `StatsFilter.Apply`：`StateOnly` 保留类别，只去掉应用名和标题，不再合并成「未公开类别」。
- `StatsViewBuilder`：状态图例去掉 `relax`，换成 `video`（视频）、`game`（游戏）。`StateKey` 按类别区分；时间轴 `UsageSpan` 增加类别，相同状态和类别才连在一起。「未公开类别」图例只剩旧版本客户端回复的数据会用到。
- 文案：删除 `Legend_Relax`（中英文），新增 `Legend_Video`、`Legend_Game`。房间隐私设置里「只显示状态」的说明改为说明只显示工作、聊天、视频等状态，不显示应用和标题，按 `deskpal-ui-copy` 写。
- 「我的状态」按当前房间隐私显示，随之变化。

### 第 2 条：在统计里更改分类，查询时重新归类

- 入口：自己的统计「类别」「标题」排行里，能确定进程名或域名的行可以点，弹出和「分类」页相同的选择对话框，保存后写入个人分类（`rules.set`，和状态页「纠正分类」是同一份数据，按账号保存在 Server，所有电脑通用）。之后的识别同样按新分类。查看房间成员的统计时不能点。
- 片段增加两列：`Process`（进程名）和 `BaseCategory`（不看个人分类时的类别，即内置规则、推测或默认的结果）。`Category` 仍是记录时的类别，不改写。`DailyRollups` 同样加这两列（重建表，主键包含这两列）。导出、同步的 JSON 里 `ExportedSegment`、`ExportedRollup` 加可空的 `process`、`baseCategory`，旧版本客户端忽略。
- 读取时重新归类（`UsageReclassifier`）：`UsageService` 汇总前，对每个片段和每日汇总用当前的个人分类重新判定类别和状态：应用名是域名的按域名、标题关键词、进程名匹配（和实时识别浏览器的顺序一致），其他按进程名匹配；没有进程名的旧记录按应用名和个人分类的名称相同来匹配。没有命中时用 `BaseCategory`，旧记录没有 `BaseCategory` 时用记录时的类别。所以删除个人分类（「恢复默认」）后历史也会恢复。
- 同步：个人分类按账号保存，每台电脑查询时用同一份个人分类，看到的历史结果一致；同步副本里是原始记录，不需要重新上传。
- 房间成员查看公开统计时，回复内容来自重新归类后的结果，再按隐私过滤。
- 导出的文件是原始记录。
### 第 3 条：今天不显示对比

- `StatsViewBuilder.Compare`：查看的是今天时返回空。删除 `Stats_YesterdayTotal`（中英文）。
- 过去的日期、周、月的对比不变。

### 第 4、5、6 条：分类调整

按影响从大到小：

1. **只认前台程序自己播放的媒体。** `MediaSignal.SourceApp`（系统媒体控制里的来源程序）和前台进程名对得上，才算「前台在播放」。`Heuristic` 的全屏视频判断、`BuildDetail` 用媒体标题、空闲豁免都改用这个条件。修掉 FF14 记成视频、游戏标题变成视频标题。
2. **浏览器里正在播放的视频算视频。** 前台是浏览器、这个浏览器有媒体在播放，并且媒体标题出现在当前标签页标题里（说明播放的就是当前页），归为视频，应用名仍是域名，详情是页面标题。暂停、在搜索页、在动态页时仍是浏览网页。不靠域名名单，Plex、Jellyfin 这类自建站点也能识别。周末数据里 B 站视频页的标题包含媒体标题（例如 FF14 那一段的媒体标题就是旁边 B 站页面标题去掉「_游戏热门视频」）。个人分类仍然优先。
3. **看视频不算暂离。** 前台是视频（包括上一条的浏览器视频、规则库里的播放器）并且在播放时，没有输入也不算空闲，不再要求全屏。规则库里的播放器（PotPlayer、VLC 等）即使不支持系统媒体控制，前台时也不算空闲。
4. **规则库（版本 5）：**
   - 新增游戏：`ffxiv_dx11`、`ffxiv`（FINAL FANTASY XIV），以及常见非 Steam 游戏的进程名。
   - `steam`、`steamwebhelper` 从游戏改为其他（显示「正在使用 Steam」）。玩 Steam 游戏时前台是游戏本身，仍靠 `steamapps` 路径识别。
   - 新增播放器：`mpv`、`mpc-be64`、`PotPlayer64`、`Plex`、`JellyfinMediaPlayer`、`kodi`、`QQPlayer`、`Thunder`（迅雷影音）等，以实际进程名为准。
5. **非 Steam 游戏的路径推测。** 和 `steamapps` 一样按安装路径推测为游戏：`\Epic Games\`、`\WeGameApps\`、`\XboxGames\`、`\GOG Galaxy\Games\`、`\Riot Games\`、`\HoYoPlay\`、`\miHoYo\`、`\Ubisoft Game Launcher\games\`、`\EA Games\`、`\Battle.net\` 下的游戏目录、`FINAL FANTASY XIV`。登录器本身（`sdologin`、`EpicGamesLauncher`）不算。
   - 备选：Windows Game Bar 在 `HKCU\System\GameConfigStore\Children` 记录了系统认定为游戏的程序路径，普通用户可读。这台工作电脑上是空的，要在家里那台电脑上看一下有没有 FF14、Sumire 再决定要不要用。
6. **标题去掉计数。** 记录和发送前，去掉窗口标题开头的未读数「(12) 」、Telegram 结尾的「– (255549)」和不可见的方向字符。只影响详情文字，不影响分类。
7. **浏览器域名跟上标题。** 前台浏览器的标题变化时立即重新读取地址栏（现在每 2 秒一次）；域名还没读到时，统计不切新片段，沿用上一个片段。减少空域名和错配的片段。

不改：分类顺序仍是个人分类优先；浏览器的内置网站规则仍不用于默认分类（视频由第 2 点判断，不按域名）；隐私过滤、防抖、状态优先级的语义不变（空闲豁免的条件按第 3 点放宽）。

### 第 7 条：跟随账号的设置

分两条路，互不影响。

**统计相关，用 PIN 码。** 「不记录标题」和「详细记录保留时长」。

- 内容是 `{ noTitleRules, retentionDays }`，用同步密钥加密后上传，和每天的统计一样。
- Server：`Users` 加 `StatsSyncSettings`（密文）和 `StatsSyncSettingsRevision`（迁移 `AddStatsSyncSettings`）。新增 `GET`、`PUT /api/me/stats-sync/settings`；`StatsSyncStatusDto` 加 `settingsRevision`（没有保存过时为空）。关闭同步时一起删除。大小上限 64 KB，超过返回 `statsSync.invalid`。Server 不解析内容。
- 客户端 `StatsSync`：每次同步先比较版本，Server 较新就下载并覆盖本机；本机改过就上传。开启或输入 PIN 码后本机记下的版本清空，所以账号上已有时先下载，没有时上传本机。
- 应用到本机后刷新统计页。保留时长变短时按现有逻辑折叠过期日期。关闭同步时 Server 上的副本删除，本机设置保留。

**暂离时长，登录就同步，明文。** 不依赖「同步到服务器」和 PIN 码。

- 设置页增加「暂离」：无操作超过所选时间后显示暂离。选项 1、5、10、15、30 分钟，默认 5。现在只有 `settings.json` 的 `idleMinutes`，界面上不能改。
- Server：`Users` 加可空的 `IdleMinutes`（同一迁移）。`GET /api/me` 返回它；新增 `PUT /api/me/idle-minutes`，只接受上面五个值，否则返回 `prefs.idleMinutes`。
- 登录和启动后拉取：Server 有值就覆盖本机并立即生效（`IdleCollector` 下一轮就用新值）；没有值就把本机的上传上去。在设置里修改后立即上传。
- 单点登录下同一时间只有一台电脑在线，另一台下次登录时拿到最新值。

## 不改什么

- 实时状态协议：`Envelope`、`PresenceSnapshot`、`RuleDto` 不变。规则库版本号加 1，走现有的全量下载。
- Server 不解析同步副本和设置副本。
- 「不记录标题」、保留时长、导入导出、清除的行为不变。导入旧版本导出的文件仍可用（没有新字段）。
- 第 6 点的标题去计数不改历史记录。
- 同步文件夹不同步统计设置。

## 风险点

1. **「只显示状态」放宽了。** 已经把视频、游戏设为只显示状态的人，升级后房间成员能看出是视频还是游戏。用户决定不在更新内容里单独说明。
2. **浏览器视频判断依赖系统媒体控制。** Chrome、Edge、Firefox 都会上报，但有的网站不给媒体标题，或标题和页面标题对不上，这时仍是浏览网页。需要在家里电脑上用 B 站、Plex、Jellyfin 各试一次。
3. **媒体来源名和进程名的对应。** 系统媒体控制给的是 AppUserModelId（例如 `MSEdge`、`Chrome`），不一定等于进程名。建一张浏览器和常见播放器的对应表，对不上的按「不是前台在播」处理（宁可少报视频）。
4. **看视频不算暂离之后，开着视频离开电脑会一直算看视频。** 前台程序自己在播放时才豁免；不支持系统媒体控制的播放器只在全屏时豁免（和现在一样）。
5. **查询时重新归类的性能。** 月视图要遍历一个月的片段；个人分类按字典匹配，预计可以忽略。用周末数据量的 30 倍测一次。
6. **旧记录没有进程名和默认类别。** 本版本之前记录的桌面应用只能按名称匹配，删除个人分类后也回不到默认，统计排行里也不能点（不知道进程名）。只有最近几天的数据受影响。
7. **规则库把 Steam 改成其他会影响所有用户。** 别人的个人分类不受影响。
8. **统计设置以账号为准。** 两台电脑都在离线时改了设置，后同步的那台的修改会被覆盖。单点登录下同一时间只有一台电脑在线，影响小。
9. **硬约束第 4 条要补一句**：开启同步时，Server 还保存一份用 PIN 码加密的统计设置。暂离时长是明文的一个整数，不含使用内容。
10. **暂离时长以账号为准。** 两台电脑都离线改过时，后登录的那台会被账号上的值覆盖。单点登录下影响小。
