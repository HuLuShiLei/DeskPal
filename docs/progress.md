# DeskPal 进度

开工前先读这份，了解哪些已经定了。口径变了就改「已定」里对应的一行（写决定和原因）；改动历史看 git log，这里不记流水账。

## 已定

| 主题 | 决定 | 原因 |
|---|---|---|
| 采集方式 | 不截图、不装钩子、不注入、不提权，只用普通用户权限的 API | 用户要求不截图；钩子和注入会被公司 EDR 当成键盘记录器 |
| 分类 | 个人分类优先，再用内置规则和推测。没有房间规则。只保留视频和游戏两类放松。音乐、购物、社交网站、新闻、阅读不再产生。用户不需要自己配置进程名和域名 | 用户要求只看当前焦点，并把网站类并进正在浏览网页 |
| 个人分类 | 「纠正分类」只改自己的识别结果，所有房间通用（2026-11-19 起保存在本机，按账号区分；开启「同步到账号」或个人数据的同步文件夹后才在电脑之间同步，见「个人数据」一行），不影响房间里的其他人（我的微信算工作，别人的微信仍是聊天）。识别结果照常广播，别人看到的是我自己的分类，例如“工作中 · 微信”；应用名是否显示仍按该房间的隐私设置 | 用户要求分类不影响他人、换房间不用重新设置，同时别人能看到我的分类 |
| 规则库改进 | 第一次打开面板时询问是否分享使用数据，设置里可以改。同意的用户上报没有规则的桌面应用（落到其他的，和按安装目录推测出类别的）的进程名、应用名称、推测的类别和当天分钟数，个人分类也参与统计；不传窗口标题、网页和具体时间。注册满 3 天的账号才计票，一人一票。至少 2 人且三分之二一致的个人分类、至少 2 人推测一致的游戏写进候选 PR；只有一人改过的分类（包括规则库里已有的应用）和没有识别的应用列在 PR 说明和 issue 里人工判断。测试阶段每天由 GitHub Actions 运行，人工审核后合并 | 用户要求规则库随使用自动完善、不纯靠人工；像游戏一样首次询问；候选走 PR 人工审核。2026-11-21 用户反馈规则库里已有的应用分错了没有改进入口、游戏名显示成 `xxx-Win64-Shipping`，要求降低门槛、每天一次 |
| 窗口外观 | 不用系统标题栏，标题栏、最小化、关闭画在页面里，和应用风格一致；保留 Windows 11 圆角和阴影。颜色跟随系统浅色、深色模式，控件按 Windows 11 样式，页面不能选中文字、不显示手形光标 | 用户觉得原生标题栏难看，界面太像网页 |
| 面板大小 | 可以拖动边框调整，默认 420×680，最小 400×480，不能最大化。拉宽时内容最宽 640px 居中；最小宽度下设置名称不折行、页面不横向溢出。重新启动后回到默认大小 | 用户要求不要锁死窗口大小，同时界面不能变形 |
| 置顶小卡片 | 状态页成员行右侧只放大头针图标，不放文字按钮。每个置顶的成员一张卡片，人数不限。切换房间（包括选「无房间」）或该成员不在房间里时移除，重新进入不恢复，不保存。面板最小高度不变 | 用户想把窗口缩小置顶，只关注房间里某个人的状态 |
| 关闭窗口 | 点关闭默认询问：最小化、最小化到系统托盘，或直接退出，可勾选不再提示。设置「关闭窗口时」可选每次询问、最小化、最小化到系统托盘、直接退出。托盘菜单仍有「退出」 | 用户要求点关闭时选择，文案按常见桌面软件 |
| 暂不显示 | 状态页不显示「房间成员看到」 | 用户要求先收起 |
| 戳一下、手动状态 | 已删除，客户端不再发送也不再处理 `interaction.poke`，Server 拒绝这种消息。`PresenceState.Custom` 和 `CustomText` 留在协议里，旧版本客户端发来的手动状态仍按文字显示 | 用户要求功能和代码完全移除 |
| 我的状态 | 状态页「我的状态」按当前房间的隐私设置显示，和房间成员看到的一致，不另加说明。鼠标指向状态、应用名、标题时，气泡显示不经过滤的类别、应用和标题，只给自己看。无房间时显示本机识别的全部内容。新状态的倒计时放在标题行右侧，进度条贴卡片底边，不改变卡片高度。还没有收到状态的房间成员右上角留空 | 用户反馈只显示类别和应用时卡片上仍有标题，容易误以为发出去了；之后要求去掉灰字说明改为悬停查看，倒计时出现和消失时下方内容不能上下跳动 |
| 屏蔽房间成员 | 任何成员都可以在房间页屏蔽另一名成员，双向生效：互相收不到对方的状态。由 Server 在转发、补发和离线广播时过滤，客户端不参与。被屏蔽的人不会收到任何通知，只会收到一条屏蔽者的离线，之后屏蔽者在对方那里一直显示离线；房间列表里看不到别人的屏蔽记录。屏蔽者的状态页显示「已屏蔽」，不能置顶，已有的置顶卡片关闭。屏蔽按房间记录，退出后再加入仍有效，解散房间时删除。取消屏蔽后双方互相补发最新状态 | 用户要求对某个成员不分享也不接收；出于社交礼仪，被屏蔽的人不能知道自己被屏蔽 |
| 识别不出来 | 归为 `Other`，标题显示“其他活动”，应用名在下一行，不算放松 | 宁可少报放松，不误报；用户要求和其他状态一样分两行 |
| 麦克风 | 不采集，没有“会议中” | 麦克风被占用也可能是语音聊天或打游戏 |
| 聊天软件分类 | QQ、微信、Telegram 等个人聊天归为 `Communication`（在聊天）；企业微信、飞书、钉钉、Outlook、会议软件归为 `Work` | 用户选定 |
| 工作和生活都常用的应用 | 内置规则归为 `Other`，显示“其他活动”和应用名：远程桌面（向日葵、ToDesk、远程桌面连接等）、虚拟机和安卓模拟器、文件资源管理器、Everything、记事本、PDF 阅读器、AI 助手（Claude、Codex、ChatGPT、OpenCode、WorkBuddy 归为工作）、翻译、笔记软件、个人邮箱（QQ 邮箱、网易邮箱、Gmail、Foxmail 等）、剪映。只有对大多数人明确是工作或放松的应用才归为 `Work`、`Video`、`Game`；个人习惯用「纠正分类」 | 用户认为远程桌面这类应用不该被强行归为工作 |
| 界面文案 | 书面用语：工作中、在聊天、正在浏览网页、其他活动、在看视频、在玩游戏；不用“忙”“摸鱼”。本机识别分标题、应用、详情三行。页面上写「房间」，不写 Room | 用户要求 |
| 多语言 | 简体中文和英文。所有给用户看的文字都在客户端（resx 和 `web/src/i18n/`），Server 只返回错误码和参数，不做多语言。设置里可选跟随系统、简体中文、English，立即生效。更新内容同样按界面语言显示。内置规则的应用名在规则库里写 `names.en`，发送和保存的仍是默认名称（中文），由接收方按自己的界面语言翻译，不改协议 | 用户要求文案从代码里抽出来、只由客户端提供；用户要求内置规则库支持多语言 |
| 服务器地址 | 登录页和设置页不显示、不能修改服务器地址，连接失败的提示不带地址。联调只改 `settings.json` | 用户要求不让用户看到服务器地址 |
| macOS 版 | 2026-11-19 起有 macOS 客户端（`src/DeskPal.Client.Mac`，AppKit + WKWebView，macOS 13+），功能和 Windows 版相同，和 Windows 用户同房间。平台无关的服务抽到 `DeskPal.Client.App` 两端共用，Windows 版行为不变。先出未签名的测试版，Apple 芯片和 Intel 各一个安装包，CI 预留签名和公证开关（`MAC_SIGN`）。读窗口标题和网址只申请「辅助功能」，不申请屏幕录制和输入监控 | 用户要做 Mac 版；没有 Apple Developer 账号；要求两种芯片都支持、抽共享层而不是复制一份 |
| Linux 版 | 2026-11-23 起有 Linux 客户端（`src/DeskPal.Client.Linux`，GTK 4 + WebKitGTK 6.0，AppImage），和 Windows、macOS 用户同房间，Server 不改。“当前在用哪个窗口”由识别来源提供：X11 和 GNOME（自带扩展）内置，其他桌面由用户写识别插件（外部程序，标准输出每行一个 JSON）。插件只在 Linux 开放，Windows 和 macOS 不变。Linux 上没有置顶小卡片和面板置顶，内置来源不读浏览器网址 |
| 插件 | 2026-11-23 起三个平台的当前窗口、网站、暂离、锁屏、媒体都由插件提供。各平台的采集器是官方插件（在程序内运行），用户插件是插件文件夹里的程序；设置里的插件列表有先后，每一项分别取最上面一个开启的、提供它的插件。Linux 官方插件带浏览器扩展（本机 HTTP）读网站。用户插件默认关闭 |
| 按标题分类 | 2026-11-24 起桌面应用可以按窗口标题分类（个人分类新增 `AppTitle`：进程名 + 标题关键词，优先于整个应用的分类）。入口和应用分类的口径一致：首页「纠正分类」勾选「只在窗口标题包含以下文字时」，统计里标题详情的「更改分类」；规则页可以修改、删除，不能添加。和其他个人分类一样跟随「个人数据」同步。已记录的统计按标题重新归类。浏览器仍按域名和标题关键词 | 用户要给微信写插件，按聊天对象分成工作和聊天；改进程名的做法不可行 |
| 补充标题插件 | 2026-11-24 起用户插件可以声明 `detail` 和 `apps`，在这些应用处于前台时替换窗口标题（例如 QQ 的当前会话名），不改应用名和分类，照常经过不记录标题和隐私过滤。按插件看到的窗口标题（`window`）匹配，不在前台切换时作废，避免插件比官方插件先报时丢失；浏览器不适用。用户插件读什么由用户负责，不受 DeskPal 硬约束限制，硬约束只管 DeskPal 本身；官方不内置读窗口内容的插件，QQ 只作为 skill 里的样例（UI Automation 只读会话名元素） | 用户要求支持针对特定软件写插件，认为用户插件读什么与 DeskPal 的约束口径无关 |
| 插件页 | 设置页「常规」里只留一行「插件」入口，点进去是独立的插件页；每个插件折叠成两行，点开看详情，需要处理的默认展开；「编写插件」放在插件页顶部，在浏览器打开指南，不再单独占一行 | 用户觉得插件多了以后设置页太长，对原来的插件区不满意 |
| 浏览器 | 前台是浏览器且正在播放当前页的视频时显示“在看视频”，否则显示“正在浏览网页”，后面是域名和页面标题。不按网站名单细分。个人分类可以把某个网站改成其他类别。隐私设为“只显示状态”时仍能看出是在看视频；“显示类别和应用”时看到域名；标题只在“显示详情”时发出 | 用户要求浏览网页不做网站名单细分；正在播放的当前页视频单独算视频 |
| Room 改名 | 只有所有者可以改，1 到 30 个字符 | 用户选定 |
| 显示名称 | 设置页「账号」可以修改，1 到 20 个字符，允许重名。修改后广播 `room.memberRenamed`，房间成员和自己的其他电脑重新拉取 Room 列表 | 用户要求显示名称可以改，允许重名 |
| 界面技术 | 面板和登录页用 .NET 宿主 + 标准 WebView2 的 HTML 界面（Preact），托盘菜单保持原生；以后的桌宠用 WPF 原生透明窗口。见 [ui-tech-evaluation.md](ui-tech-evaluation.md) | AI 能在浏览器里看到和测试界面；透明窗口里的 WebView2 静止时也占 CPU |
| 面板 | 一个窗口五页：首页、统计、房间、规则、设置，用左侧导航切换（2026-11-16「状态」改名「首页」，图标改为房子；「房间」图标改为多人；2026-11-19「分类」改名「规则」，图标改为漏斗，页内切换「分类」和「不记录标题」），标题栏里切换房间。房间设置和应用设置分开。隐藏 5 分钟后释放 WebView2。更新的确认和提示显示在面板里 | 用户选定 |
| WebView2 Runtime | 安装包带 `--framework webview2`，安装时缺少就自动安装；启动时再检测一次，缺少时提示下载 | 少数 LTSC、精简版系统没有 |
| 隐私 | 按 Room、按类别配置；默认不发窗口标题。创建或加入房间时所有类别都写成“只显示状态”，要多显示由成员自己在该房间改；之前加入、没有保存过的房间仍按原来的默认值（工作、聊天只显示状态，其他显示类别和应用） | 同一个人在伴侣 Room 和同事 Room 可以显示不同程度；用户要求新房间默认只显示状态 |
| 通信 | Server 中转 + SignalR，不做 P2P；以后加端到端加密 | 公司网络打洞成功率低；多人 Room 和离线状态需要 Server；见 plan-v1 第八节 |
| Server 职责 | 只按 `Type`、`RoomId` 和 `To` 路由，不解析 Payload；实时状态只在内存里 | 给端到端加密留位置，少存数据 |
| 房间 | 可以加入多个房间，同一时间最多进入一个，也可以在标题栏的房间菜单里选「无房间」。一个房间都没有时同样是无房间。这时所有房间都看到离线，状态不发给任何房间，标题栏显示「无房间」，状态页和房间页的提示都是「当前无房间。请创建或选择一个房间，也可以用邀请码加入。」切换时给上一个房间发离线，房间仍留在列表里，再次进入不用邀请码。主动退出才会从列表移除，之后仍可用邀请码加入。人数上限来自 `MaxMembersPerRoom`，默认 20；已有房间在列出或有人加入时改成当前配置 | 用户要求先支持多人，并把人数上限从 8 配置成 50，之后改为 20；之后要求可以不进入任何房间，并把这种状态和还没有房间统一称为「无房间」 |
| 踢出 | 只有所有者可以踢出其他成员。被踢出的人从成员列表和自己的房间列表里消失，当前邀请码不能再次加入。邀请码换成新的之后可以重新加入。解散房间时这条记录一起删除 | 用户要求踢出后不能从列表里看到；邀请码更新后允许再加入 |
| Room 生命周期 | 参考 QQ 群：不自动删除；每人最多拥有 5 个 Room；所有者要先转让才能退出；所有者可以解散 | 用户选定 |
| 邀请码 | 每个房间一定有邀请码：创建房间时生成，已有房间没有时在查看时补上（不解除踢出限制）。不过期，所有者重新生成后旧码才失效。所有成员都能在房间页的「当前房间」卡片里反复查看和复制，只有所有者能重新生成；重新生成前确认，会解除踢出限制。复制时客户端先向服务器取最新的码 | 2026-11-16 用户要求，原来是 24 小时过期、任何成员都能生成、只在生成时弹出一次 |
| 技术栈 | .NET 10：WPF 托盘客户端，ASP.NET Core + EF Core + SQLite，JWT，Docker 镜像（GHCR）+ Portainer + 已有 Traefik | 用户指定 C#，有自己的服务器 |
| 检查更新反馈 | 手动点击后，设置页立即显示「正在检查更新…」，按钮变为「请稍候…」；下载过程显示「正在下载新版本 x（百分比）」。不使用 Windows 通知气泡。后台定时检查不显示这些过程，下载完成后设置页的「立即重启并更新」变为可用。检查更新调用 GitHub API，未登录时每个出口 IP 每小时 60 次：手动检查 5 分钟内沿用同一通道上次「已是最新」的结果；GitHub 返回 429，或 403 且额度用完、带 Retry-After 时，到恢复时间之前（1 分钟到 1 小时）手动和后台检查都不再请求，提示「检查更新过于频繁，请在 HH:mm 后再试。」 | 用户要求点击和下载都要有反馈，并去掉检查更新的通知气泡 |

- 个人分类和自定义标题栏：模拟数据下在浏览器里逐页检查过浅色和深色。真实客户端端到端检查过：全新数据库依次应用三个迁移；首次打开时询问分享，同意后 Server 和本机都记为同意；标题栏拖动窗口、圆角边框；个人分类保存后只有本人的客户端收到 `rules.personalChanged` 并更新缓存，其他成员只收到状态；`Work` 设为显示类别和应用时，对方收到“工作中”和应用名。

## 偏离方案

| 方案 | 实际 | 原因 |
|---|---|---|
| 客户端一个项目 | 拆出 `DeskPal.Client.Core` | 纯逻辑可以在 net10.0 下单元测试 |
| `SetWinEventHook` 事件驱动 | 每秒轮询 `GetForegroundWindow` | 更简单，不依赖消息循环；开销可以忽略 |
| Windows Toast 通知 | 托盘气泡 | 少一个依赖；不需要注册 AppUserModelID |
| 麦克风占用算开会 | 不采集麦克风，不再产生 `Meeting`。枚举成员保留 | 麦克风被占用也可能是语音聊天或打游戏 |
| 内置规则按增量更新 | 版本号不同就全量下载 | 规则只有几百条，全量下载更简单 |
| 前置 Caddy 自动配置 HTTPS | 用已有的 Traefik（DNS challenge 泛域名证书），对外地址 `https://deskpal.hafuhafu.cn:36443` | 用户已有 Traefik；运营商封了 80/443 |
| 端口 | 本地开发用 5180 | 5284 被 QQ 占用 |
| 数据库目录 `data/` | `storage/` | Windows 不区分大小写，会和源码目录 `Data/` 冲突 |
| 使用统计存在 `usage\usage.db` | 每个账号一个文件 `usage\<userId>.db` | 同一台电脑换账号登录时不混在一起 |
| `SqliteUsageStore` 放在 Client | 放在 Client.Core | 不依赖 Windows，可以直接单元测试 |
| 导出选日期范围，导入后按设备筛选 | 导出全部数据，导入后直接合并，不按设备筛选 | 单点登录后同一时间只有一台电脑在记录，按设备筛选用处不大；按 `deviceId + 开始时间` 去重仍然保留 |
| 成员开关公开后，其他人重新拉取房间列表才看到入口 | 新增 Server 消息 `room.memberSharingChanged`，其他成员立即重新拉取 | 方案没写怎么刷新「查看统计」按钮 |
| 请求只带查看范围 | 请求里另带上一周期 `PreviousFrom`、`PreviousTo` | 对比上一周期时不用再请求一次；上一周期超出公开天数时不回复对比 |
| 同步的密钥和每天的哈希存在 `settings.json` | 密钥存在 `usage\<userId>.sync-key`（密钥用 DPAPI 加密），每天的哈希和版本号存在使用统计库的 `SyncDays` 表 | 清除统计时一起清掉；不用每次上传都改写 `settings.json` |
| 按哈希判断哪些日期要下载 | Server 给每次上传分配递增的版本号（`Users.StatsSyncRevision`），客户端下载版本号比本机已知的新的日期 | Server 不需要知道明文哈希，判断更简单 |
| 关闭状态下不发任何同步请求 | 关闭时仍定时查询一次状态（`GET /api/me/stats-sync`），不上传也不下载 | 要知道是否已在其他电脑开启，才能显示「输入 PIN 码」 |
| 退出登录时删除本机密钥 | 先同步一次（最多 5 秒）再删除 | 退出前最后几分钟的记录也能到 Server |
| 「输入 PIN 码」是行内按钮，和开关并排 | 放在说明文字下面 | 和开关并排时 400px 宽度下标题会折行 |
| 错误码只有方案里的四个 | 另加 `statsSync.invalid`（盐、校验值为空或超长，上传的不是 base64） | 请求格式错误时要有错误码 |
| 下载后按现有导入逻辑合并（`deviceId + 开始时间` 去重） | 按电脑和日期整份替换其他电脑的记录（`MergeDay`），本机记录不动 | 导入逻辑只补缺少的：另一台电脑还在变长的片段不会更新，另一台电脑折叠过期片段后本机会同时有片段和汇总而翻倍 |
| 同步开启时清除全部统计，同时清空 Server 上的副本 | 同步开启时不能清除，要先关闭；删除 `DELETE /api/me/stats-sync/days` | 2026-11-13 用户要求和同步文件夹统一 |
| macOS 的 token 和同步密钥放在钥匙串 | 放在 `local.key`（权限 600）加密的文件里 | 未签名的应用每次更新后钥匙串会当成另一个应用，弹出登录密码提示；保护程度和 DPAPI 当前用户相同 |
| macOS 开机自启用 `SMAppService` | 用 `~/Library/LaunchAgents` 的 plist | 不依赖签名，能带 `--minimized` 参数 |
| 同步文件夹退出登录时只删除密钥、保留路径 | 退出登录时整份删除（路径和密钥），重新登录后再次选择文件夹 | 少一种「有路径、没密钥」的状态，重新选择时会自动识别已有的同步数据 |
