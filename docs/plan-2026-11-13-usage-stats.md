# 使用统计（本机记录 + 房间内按需查看）

阶段 0 计划。确认前不改业务代码。替代路线图阶段 2 的「当天时间轴」。

## 这次做什么

1. 客户端在本机持续记录自己用电脑的时间都花在哪里，可以按天、周、月查看，类似手机的「屏幕使用时间」。
2. 统计分三个细粒度：状态（工作中、在聊天、放松、暂离……）、类别和应用（含浏览器域名）、标题（窗口标题、页面标题）。直接复用现有的 `PrivacyLevel`：`StateOnly`、`Category`、`Detail`。
3. 数据只存在本机 `%APPDATA%\DeskPal\usage\`，可以导出、导入、清除。
4. 每个房间一个「公开使用统计」开关，默认关闭；打开后可以选别人能看多久：1 天、3 天、7 天、30 天。细粒度不单独设置，按该房间现有的按类别隐私设置：工作设为显示详情，别人看到的工作统计就到标题；游戏设为显示类别和应用，游戏统计就到应用名。房间里没有被屏蔽的成员可以查看。
5. 查看时由对方客户端在本机汇总后返回结果。Server 只转发，不保存，不解析内容；内容用每次请求临时协商的密钥加密，Server 看到的只是密文。

## 已定（2026-11-13）

| 主题 | 决定 |
|---|---|
| 公开级别 | 房间里只有一个开关。打开后每个类别的细粒度等于该房间实时状态的隐私级别，不另设 |
| 对方不在这个房间 | 只有对方当前正在这个房间才响应；在别的房间或「无房间」时不响应，和实时状态一致 |
| 暂停分享 | 照常在本机记录，暂停只影响分享 |
| 他人可查看范围 | 每个房间单独设置：1 天、3 天、7 天、30 天，打开开关时默认 7 天 |
| 查看记录 | 被查看的人在统计页看到「最近 7 天谁查看过」 |
| 本机文件 | 不加密，和 `settings.json`、日志一样放在用户目录，由用户自己保管；导出文件同样是明文 |
| 对方离线 | 看不到统计，不做离线缓存，也不做加密上传 |
| 多台电脑 | 已改为同一账号同一时间只能在一台电脑上登录（2026-11-13 已实现），统计不再有多台电脑重复计时的问题 |
| 排期 | 一次做完。下文「一期」「二期」只表示实现顺序：先做本机部分并自测，再做房间部分 |

「屏蔽房间成员」已在 main（`cd51528`），房间部分直接复用它的屏蔽判断。

## 这次不做什么

- 不上传任何统计数据到 Server，不新增数据库表。对方离线时看不到，不做离线缓存。
- 不做 WebRTC 等 P2P 直连（公司网络打洞成功率低，最后仍要 TURN 中转，见 plan-v1 第八节）。
- 不改 `presence.update` 的流程、防抖时间、`PrivacyFilter` 对实时状态的语义。
- 不改「分享使用数据」（`UsageReporter`、`UnknownAppReports`）。它们和本功能互不影响。
- 不新增 `ActivityCategory`、`PresenceState` 成员。
- 不做排行榜、房间内对比，不做「谁看过我的统计」之外的社交功能。

## 行为口径

### 记录（一期）

- 记录点：`PresenceResolver` 的结果，不经过防抖和隐私过滤。防抖会吞掉 10 秒以内的切换，统计要的是实际时长。
- 按「片段」记录：开始时间、结束时间、状态、类别、应用名、标题。状态、类别、应用、标题任一变化就结束上一段、开始新的一段。
- 两次判定间隔超过 30 秒（睡眠、休眠、进程卡住）时，上一段在最后一次判定时刻结束，中间不计。和 `UnclassifiedUsage` 一致。
- 跨本地零点的片段在零点切开。按本机时区算日期，换时区不回溯修改。
- 锁屏、暂离照常记录，图表里单独显示为「暂离」「已锁屏」，不计入「使用时长」。
- 暂停分享期间照常记录。
- 每分钟或片段结束时写盘，客户端崩溃最多丢 1 分钟。
- 「不记录标题的应用」：个人可以列出应用或域名（例如网银），这些应用只记类别和应用名，不记标题。

### 存储

- 本机 SQLite：`%APPDATA%\DeskPal\usage\usage.db`，两张表：
  - `Segments`：原始片段，默认保留 90 天，过期自动删除。
  - `DailyRollups`：按 日期 × 状态 × 类别 × 应用 × 标题 预汇总的分钟数，长期保留（只按天，没有具体时刻）。原始片段过期后，历史查询用它。
- 估算：每天 1000 到 3000 个片段，带标题约 0.3 到 0.6 MB/天，90 天约 50 MB；`DailyRollups` 一年约 10 到 20 MB。
- 设置里可以改保留天数、立即清除全部数据。卸载不删除（和 `settings.json` 一致）。
- 换账号时按 `userId` 分库，不混用。

### 导入导出

- 导出：选日期范围，生成一个 JSON 文件（`schemaVersion`、`deviceId`、`segments`、`rollups`）。用系统保存对话框，路径由用户选。
- 导入：校验版本和结构，单个文件上限 100 MB。按 `deviceId + 开始时间` 去重，重复导入不会翻倍。导入后在统计页可以按设备筛选。
- 用途：换电脑时迁移；把公司电脑和家里电脑的数据合到一台上看。

### 图表（一期，「统计」页）

左侧导航新增「统计」页。顶部切换「日 / 周 / 月」和细粒度「状态 / 类别 / 标题」，左右箭头翻页。

| 视图 | 图表 | 说明 |
|---|---|---|
| 日 | 24 小时时间轴（一条横向色带，按状态着色）+ 每小时堆叠柱 | 时间轴看「什么时候在干什么」，柱看「每小时干了多少」 |
| 周、月 | 每天一根堆叠柱，按状态或类别分色；上方显示日均使用时长和与上一周期的差 | 点某一天进入日视图 |
| 所有视图 | 排行列表：按选中的细粒度列出前 20 项，带横向占比条和时长 | 和手机屏幕使用时间的应用列表一样 |

- 不用饼图：类别多时难比较，手机屏幕使用时间也是柱 + 列表。
- 用手写 SVG，不引入图表库。ECharts 约 1 MB，Chart.js 约 200 KB，这几种图手写约 300 行。
- 颜色复用现有 `Tone`（work、chat、relax、browse、other、away）。
- 汇总在 C#（Client.Core）里算好放进结果里，页面只画，和现有 `PanelState` 的做法一致。统计数据按需请求（`stats.query` 命令），不放进每 200 毫秒推一次的 `PanelState`。

### 房间内公开（二期）

- 房间隐私设置里增加开关「公开使用统计」，默认关闭；创建或加入房间时为关闭。开关下面是「可查看最近」：1 天、3 天、7 天、30 天，打开时默认 7 天，改完立即保存（和按类别隐私设置一样）。
- 打开后，每个类别的统计细粒度等于该房间这个类别的实时隐私级别（只显示状态 / 显示类别和应用 / 显示详情）。之后改了按类别的隐私设置，统计跟着变，下一次查看生效。
- 打开开关时，如果有类别是「显示详情」，确认对话框列出这些类别：「房间成员可以看到这些类别最近 N 天的窗口标题和页面标题」，N 是当前选的天数。
- 开关和天数存在 Server 的 `RoomMembers.PrivacyProfileJson` 里（新增 `ShareStats`、`StatsDays`，JSON 字段，不需要迁移），`RoomMemberDto` 末尾增加 `shareStats`、`statsDays`，用来决定是否显示「查看统计」按钮，以及他人视图里能往前翻几天。这只是设置，不是统计数据。
- 真正的判断在数据所有者的客户端：收到请求时按本机读到的开关、天数、该房间的隐私级别、屏蔽记录，以及自己当前是否正在这个房间再判断一次；请求范围超过天数的部分不返回。Server 的记录被改了，也拿不到没公开的数据。
- 查看入口：状态页成员行增加「查看统计」，打开统计页的他人视图，图表和自己的一样。细粒度切到「标题」时，没有公开到标题的类别显示为应用名或状态，并标注「对方未公开标题」。

### 请求和响应（二期）

- 新增两个客户端消息：`stats.request`、`stats.response`。`Envelope` 末尾新增 `To`（`Guid?`，目标用户），只有这两种消息使用。
- Server 对这两种消息：发送者和 `To` 都是 `RoomId` 的成员，且双方没有互相屏蔽，才转发给 `To` 的连接；否则丢弃，不告诉发送者原因。Server 不读 Payload。
- 限频：每个用户每分钟最多 10 次 `stats.request`，超过的丢弃。数据所有者的客户端对同一个请求者、同一个范围缓存 60 秒。
- 请求者 30 秒没有收到响应，页面显示「对方不在线或没有响应」。
- 响应只含汇总结果（按天的分钟数、前 20 项排行、单日的时间轴片段），不发原始片段。单日时间轴在「状态」细粒度下只含状态和起止时间。
- 体积：SignalR 默认单条上行消息上限 32 KB。汇总后一般在 10 KB 以内；Server 把 `MaximumReceiveMessageSize` 调到 128 KB，客户端超过 100 KB 时截短排行再发。
- 被查看的人在统计页看到「最近 7 天谁查看过」：查看者、房间、时间，只记在本机，7 天后删除。

### 加密（二期）

- 每次请求，请求者生成临时 ECDH（P-256）密钥对，把公钥放进 `stats.request`。数据所有者同样生成临时密钥对，协商出共享密钥，用 AES-GCM 加密响应，把自己的公钥和密文放进 `stats.response`，`Enc` 为 `ecdh-p256-aesgcm`。
- 全部用 .NET 自带的 `ECDiffieHellman`、`AesGcm`，不加依赖。
- 能防：Server 日志、反向代理日志、内存转储里出现统计明文；Server 被入侵后被动抓取。
- 防不了：Server 运营者主动替换双方公钥做中间人。要防这一层，得有成员身份密钥和指纹确认，留给路线图阶段 3 的端到端加密。

## 风险点

1. **标题级历史比实时标题敏感得多。** 实时只暴露「此刻」，历史最长是 30 天的完整浏览记录。打开开关时对「显示详情」的类别二次确认；标题只出现在排行（前 20 项），不给带标题的逐段时间轴。
2. **改实时隐私设置会连带影响统计。** 开关打开后，把某类别改成「显示详情」，别人就能看到这一类在所选天数内的标题。隐私设置页在开关打开时加一行提示「也会影响使用统计」。
3. **对方离线就看不到。** 这是「Server 不保存」的直接代价。下班关机的人，同事永远看不到他的统计。
4. **数据可以伪造。** 统计是对方自己算的，导入功能也能写进任意数据。只适合朋友、伴侣之间看，不能作为考勤依据，界面上不要暗示可信。
5. **本机明文保存标题。** 其他 Windows 账号读不到 `%APPDATA%`，但同一账号下运行的程序可以读；`usage.db` 和导出文件被拷走就等于浏览记录外泄。设置页的数据说明里写明文件位置，提醒不要外传。
6. **Server 中间人。** 临时密钥加密挡不住 Server 运营者主动替换公钥，只能挡被动泄漏。Server 是自己的，现阶段可以接受，但要在文档里写清楚，不要对外宣称「端到端加密」。
7. **SignalR 消息大小。** 默认 32 KB，超过时连接直接断开，不是只丢这一条，所以要先在发送端截短。
