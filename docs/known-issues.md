# 已知问题和限制

修掉一项就删掉，并在 [progress.md](progress.md) 记变更日志。

## 采集

- **浏览器域名不稳定**：UI Automation 依赖浏览器的界面结构，浏览器更新后可能失效；在地址栏上用 `FindFirst(Descendants)` 查找比较慢，所以加了 3 秒超时和“上一次没返回就跳过”。切换标签后最多约 2 秒才拿到新域名，这段时间按旧域名分类。彻底解决靠阶段 2 的浏览器扩展。
- 麦克风判断只看是否有应用占用麦克风，语音输入法、录音软件也会被算成开会。
- 全屏判断按显示器边界，无边框窗口化的游戏可能识别不出来。

## 分类

- **第一次启动时没有缓存的内置规则**：要等 Server 返回以后才有内置规则，在这之前全部归为推测层或 `Other`。之后会使用本地缓存。
- **Room 规则跨 Room 合并**：客户端把所有 Room 的规则合并成一层，Room A 的纠正会影响自己在 Room B 里的分类。原型只有一个 Room，所以没问题；做多人、多 Room 时要改。

## 通信和账号

- “戳一下”在对方离线时直接丢失，没有离线消息。
- 没有 refresh token，token 30 天后过期，需要重新登录。
- 加入 Room 时的人数检查不在事务里，两个人同时用邀请码加入，可能超过人数上限。

## 工程

- 客户端日志只输出到 Debug，没有写入文件。
- 没有安装包、自动更新和代码签名，公司电脑可能有 SmartScreen 提示。
- 没有 git 仓库，也没有 CI。
