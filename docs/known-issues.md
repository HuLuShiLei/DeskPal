# 已知问题和限制

修掉一项就删掉，并在 [progress.md](progress.md) 记变更日志。

## 采集

- **浏览器域名不稳定**：UI Automation 依赖浏览器的界面结构，浏览器更新后可能失效；在地址栏上用 `FindFirst(Descendants)` 查找比较慢，所以加了 3 秒超时和“上一次没返回就跳过”。切换标签后最多约 2 秒才拿到新域名，这段时间仍显示上一个域名。浏览器扩展已不在路线图里，这个限制会一直存在。
- 全屏判断按显示器边界，无边框窗口化的游戏可能识别不出来。

## 分类

- **第一次启动时没有缓存的内置规则**：要等 Server 返回以后才有内置规则，在这之前全部归为推测层或 `Other`。之后会使用本地缓存。
- **开启同步到账号后，修改个人分类和不记录标题要连着 Server**：先写 Server 再写本机，断网时修改会失败，已有的规则仍从本机生效。未开启时只写本机，不受影响。
- **旧客户端和同步到账号**：这次改动之前的客户端（包括 0.1.4 的早期测试版）不认识这个开关。新账号默认关闭，旧客户端修改个人分类、暂离时长、偏好时 Server 返回 403 `personalSync.off`，显示通用错误；读取个人分类也返回 403，旧客户端继续用本机缓存；旧客户端仍会调用 `PUT /api/me/stats-sync/settings`，这个接口为兼容保留，新客户端不再调用。
- **同步文件夹和导出文件不加密**：个人数据的同步文件夹和导出的 JSON 都是明文，包括不记录标题的规则本身（例如某个银行的应用名）。
- **规则库候选只看桌面应用**：浏览器网页不统计、不上报。内置的网站规则本来就不参与浏览器的默认分类，想改某个网站只能用个人分类。
- 规则库候选的门槛（自动写入 2 人、三分之二一致，列出待确认 1 人，注册满 3 天）是测试阶段的值，没有数据依据。用户多了以后按 PR 的质量调高 `Rules__*`，工作流也可以改回每周。待确认的列表只有一个人时也会出现在 GitHub 上。
- 推测出来的游戏名取自 Steam 清单或游戏文件夹，多是英文；非 Steam、也不在游戏库目录和 Unreal 目录结构里的游戏，仍然显示文件描述或进程名。

## 通信和账号

- 没有 refresh token，token 30 天后过期，需要重新登录。不再计划补上，上架 Steam 后改用 Steam 会话票据登录。
- 加入 Room 时的人数检查不在事务里，两个人同时用邀请码加入，可能超过人数上限。
- 0.1.4 之前的客户端没有查看邀请码的入口。Server 更新后，旧版本里不是所有者的成员点「生成邀请码」会显示「请求失败（HTTP 403）」（旧版本不认识 `room.ownerOnlyInvite`）；所有者生成成功，但提示里的有效期是错误的日期（Server 不再返回过期时间）。登录后会自动更新。
- 0.1.2 之前的客户端没有注册邀请码输入框。Server 打开 `Auth:RequireSignupInvite` 后，用旧版本注册会失败，只显示通用错误（旧版本不认识新错误码）。登录不受影响，登录后会自动更新。
- 管理员名单只看 Server 配置，客户端在登录或调用 `/api/me` 时更新 `isAdmin`。改了名单要重启 Server，已登录的客户端下次启动才显示或隐藏设置页的「注册邀请码」；接口本身每次按当前配置判断。

## 使用统计

- **本人离线就看不到**：统计只在本人的电脑上，本人不在线、不在这个房间或客户端卡住时，请求 30 秒后提示失败。这是有意的取舍。
- **升级前的暂停期间无法区分**：这个版本之前，暂停分享时记下的使用统计没有标记。房间成员查看时仍按实际活动显示，只有之后的记录会受「包含暂停期间」影响。
- **密钥交换没有身份验证**：请求方的临时公钥经过 Server 转发，没有和账号绑定。能控制 Server 的人可以替换公钥，以中间人方式读到统计。防的是 Server 日志和数据库，不防恶意的 Server 管理员。
- **数据可以伪造**：统计由本人的电脑计算，导入功能也能写入任意数据，只适合朋友之间看，不能作为考勤依据。
- **本机明文保存**：`usage\<userId>.db` 和导出文件里有窗口标题。同一 Windows 账号下运行的程序都能读到，文件被拷走等于浏览记录外泄。
- **换电脑**：单点登录后同一时间只有一台电脑在记录。打开「同步到服务器」或「同步文件夹」后自动合并；都不打开时，另一台电脑上的记录要手动导出、导入才能合在一起。
- **同步到服务器只能拖慢破解**：8 位数字 PIN 码只有一亿种组合。本机实测 Argon2id（64 MB、3 次迭代、4 线程）派生一次约 0.13 秒，一台 16 核电脑穷举一遍约需一个多月，高端显卡可能再快一到两个数量级。拿到数据库的人（包括 Server 管理员）花时间就能读到窗口标题。所以界面只写「用 PIN 码加密」，不写「服务器无法读取」。参数写在盐里，以后可以调高，但只对之后重新开启的账号生效。
- **PIN 码不能找回，也不能修改**：忘记或想换 PIN 码时，只能关闭同步（Server 上的副本随之删除）再用新 PIN 码开启。本机数据不受影响，丢的只是还没同步到这台电脑的记录。
- **同步只合并，不删除**：开启任一种同步时不能清除全部统计，要先关闭。关闭后清除只影响这台电脑，其他电脑本机的记录还在，以后再开启同步会重新合并回来。导入的记录同样会同步到其他电脑。
- **和还按保留时长折叠的旧版本混用**：2026-11-16 起新版本不再折叠，但同一账号在另一台电脑上用旧版本时，旧版本仍每 6 小时把本机库里超过保留天数的片段折成按天汇总，包括从其他电脑同步过来的片段。旧版本上传后，新版本会用折过的版本替换「那台电脑」的记录；新版本自己记录的不受影响。升级所有电脑后不再出现。
- **使用统计只增不减**：不再按保留时长折叠，本机统计库、导出文件、同步文件夹里的文件和服务器上的密文都会一直变大。统计页按日期查询，走 `StartAt` 索引，不会因此变慢；导出、导入是整库操作，导入时整个文件读进内存，几百 MB 的文件会占用相应内存。服务器上不限制单日大小，也不限制每个账号的合计大小，只能靠名单控制人数。极大的单日请求仍可能被服务器的请求体上限拒绝。
- **移出名单会直接删除服务器副本**：名单外、已开启同步的账号，Server 启动时关闭同步并删除服务器上的副本，没有任何提示。本机数据保留，丢的只是还没同步到本机的记录。
- **同步文件夹的 PIN 码同样只能拖慢破解**：网盘服务商或拿到文件夹的人可以离线穷举 8 位 PIN 码，强度和同步到服务器相同。
- **同步文件夹依赖同步工具**：同步工具只复制了一部分、或者文件是「仅在线」的占位文件时，这一轮跳过或读取较慢，下一轮再试。没有网盘或同步工具的用户用不上。

## macOS

- **还没在真实的 Mac 上运行过**：代码只在 Windows 上对 macOS 引用程序集做过类型检查（`tools/MacCheck`），安装包由 CI 的 macOS runner 生成。采集、辅助功能授权、拖动窗口、置顶卡片、自动更新都要在 Mac 上走一遍，见 progress.md「还没验证」。
- **没有签名**：安装包是 ad-hoc 签名。第一次打开时 macOS 提示无法验证开发者，要到「系统设置 → 隐私与安全性」点「仍要打开」。macOS 按签名识别应用，**每次更新后「辅助功能」授权都会失效**，DeskPal 启动时会再弹出系统的授权提示；没有重新授权时窗口标题为空、拿不到浏览器网址，状态仍然按应用识别。有 Apple Developer 账号后在 CI 打开签名（`MAC_SIGN`）即可解决。
- **读不到正在播放的媒体（macOS 15.4 起）**：系统没有公开接口，私有框架 MediaRemote 从 15.4 起不再回答第三方应用。读不到时「全屏且正在播放算看视频」「浏览器在播放当前页的视频算看视频」两条推测不生效，显示为当前应用或正在浏览网页；IINA、VLC、QuickTime 等播放器仍按内置规则识别为看视频。更早的系统上按 Windows 的方式工作，但只是尽力而为，接口随时可能变化。
- **浏览器网址**：Safari 从网页区域读 `AXURL`；Chrome、Edge、Arc 在没有开启网页辅助功能树时读工具栏里第一个文本框（地址栏），和 Windows 的做法一样，浏览器改版后可能失效。Firefox 不一定能读到。
- **内置规则按 Bundle ID 匹配**：Mac 客户端把 Bundle ID（例如 `com.tencent.xinwechat`）当作进程名上报和分类。规则库版本 8 补了约 70 个常用 Mac 应用，其他应用要等规则库候选（每周的 PR 会出现 Bundle ID）或由用户纠正分类。没有 Bundle ID 的命令行程序用可执行文件名。
- **全屏判断**：系统全屏（绿色按钮）读辅助功能的 `AXFullScreen`；无边框全屏的游戏按窗口是否正好盖住某个屏幕判断。
- **本机密钥是文件**：token 和同步密钥用 `~/Library/Application Support/DeskPal/local.key`（权限 600）加密，不用钥匙串：未签名的应用每次更新后会被钥匙串当成另一个应用，弹出登录密码提示。保护程度和 Windows 的 DPAPI（当前用户）相同：同一个 macOS 用户下运行的程序都能读到。
- **界面**：窗口按钮仍是页面画的最小化和关闭（右上角），不是 macOS 左上角的红黄绿按钮。置顶小卡片不抢焦点，点击卡片上的按钮时偶尔要点两下。没有程序坞图标（菜单栏程序），Cmd+Tab 里也看不到。
- **开机自启**用 `~/Library/LaunchAgents/com.hulushilei.deskpal.autostart.plist`，macOS 13 起第一次会在通知中心提示「已添加后台项目」。
- **通知**：踢出、加载房间失败等提示走通知中心，第一次会请求通知权限；拒绝后不再显示。

## Linux

- **还没在朋友的电脑上运行过**：在 Ubuntu 24.04、GNOME Shell 46 上实际运行并验证过（见 changes-2026-11-23-linux.md），Ubuntu 26.04（GNOME Shell 50）和 Arch 没有。
- **需要系统里有 GTK 4 和 WebKitGTK 6.0**：安装包不带这两个库。Ubuntu 24.04 及以上自带；Arch 要装 `webkitgtk-6.0`。缺少时程序启动即退出，终端里能看到找不到库的报错。
- **只有 x64 的 AppImage**：没有 deb、rpm、AUR、Flatpak，也没有 ARM 版。运行 AppImage 需要 FUSE（`libfuse2`），没有时用 `--appimage-extract-and-run`。
- **GNOME 的 Wayland 会话要装扩展**：Wayland 下普通程序读不到当前窗口。要在「设置 → 插件 → Linux 内置」里点“安装 GNOME 扩展”，然后注销并重新登录。扩展把“当前窗口的标题、应用、进程”放在会话总线上，本机同一用户的其他程序也能读到。锁屏期间 GNOME 会停用扩展，解锁后恢复。GNOME 升级大版本后，如果新版本不在扩展声明的范围（45 到 50）内，扩展会被停用，要等 DeskPal 更新。
- **其他 Wayland 桌面要自己写插件提供当前窗口**：KDE、Hyprland、Sway、niri 等，Linux 内置插件读不到窗口，见 provider-guide.md。仓库里的 Hyprland 和 Sway 例子没有在真机上验证。没有这样的插件时只共享在线、暂离、锁屏、网站和正在播放的媒体。
- **网站要装浏览器扩展**：Linux 上从浏览器外面读不到网址，网站靠 DeskPal 浏览器扩展上报。没装时浏览器只显示“浏览中”和标题，按网站分类的规则不生效。扩展是未打包的，Chrome 系要打开开发者模式加载；正式版 Firefox 只能临时载入，重启后要重新载入，长期使用要等扩展经过 Mozilla 签名，或用 ESR、开发者版。扩展在 Chrome for Testing 158 和 Firefox 160 上验证过，Edge 和 Snap 版 Firefox 没有。
- **浏览器扩展的本机端口是固定的**（127.0.0.1:24913）：被别的程序占用时网站读不到，插件列表里会显示原因，DeskPal 每 30 秒重试。本机任何程序都可以往这个端口报一个域名（网页不行），所以它和插件一样只算“陈述”，不当作可信来源。
- **同时开着几个同种浏览器时**（例如两个 Chrome 配置），按最近获得焦点的那个算，偶尔会取到另一个的网站。
- **没有置顶小卡片、面板置顶和面板定位**：Wayland 不允许程序自己放置窗口或置顶。面板出现在桌面决定的位置。
- **托盘**：用 StatusNotifierItem。GNOME 要有 AppIndicator 扩展（Ubuntu 默认带，其他发行版的 GNOME 要自己装），并且左键点图标打开的是菜单而不是面板。没有托盘的桌面上不显示图标，再次启动 DeskPal 可以打开面板。
- **窗口最小化后再次启动 DeskPal 不一定能把它带到前面**：Wayland 下由桌面决定，GNOME 可能只弹出“DeskPal 已就绪”的通知。
- **内置规则按 Windows 的进程名匹配**：多数应用在 Linux 上可执行文件同名（`code`、`steam`、`obs`），不同名的会归到“其他活动”，要在规则库里补。
- **本机密钥是文件**：和 macOS 一样用 `~/.config/DeskPal/local.key`（权限 600），不用系统的密钥环。

## 插件

- **用户插件是以当前用户身份运行的普通程序**：DeskPal 不限制它能做什么，只运行信得过的插件。新放进文件夹的插件默认关闭，开启时要确认。插件给出的内容仍然经过分类和隐私过滤。
- **Windows 上的 `.py` 插件要能直接运行 `python`**：DeskPal 用 PATH 上的 `python.exe` 启动它，没装或不在 PATH 上时插件显示“没有正常运行”。`.ps1` 要存成带 BOM 的 UTF-8，否则 Windows PowerShell 5.1 读错中文。批处理插件里不能用 `timeout` 等待（标准输入是关闭的，它会立即返回）。
- **一个插件出错时它的能力交给下一个**：插件反复启动失败时，这几项由列表里下面的插件提供，状态不会因此中断；但插件刚启动、还没说 hello 时，按默认能力（当前窗口、网站）算，会短暂盖住下面的插件，第一次运行后就记住它声明的能力。
- **官方插件关掉后对应的几项就没有了**：例如关掉 Windows 内置又没有别的插件提供当前窗口，房间里只显示在线和暂离等。插件列表顶部会提示哪几项没人提供。
- **macOS 的插件没有在真机上运行过**：插件宿主是三平台共用的代码，在 Windows 和 Linux 上实际跑过；macOS 只做了编译检查（MacCheck）。

## 工程

- Velopack 在同一目录重新安装或卸载时会清空整个安装目录，指向已有文件的目录时会删掉其中的文件。安装向导拒绝已有其他文件的目录，覆盖安装时保留 `logs\`；绕过向导直接运行 Velopack 的 Setup.exe 没有这层保护。
- 换到新目录安装后，旧目录不会自动删除，向导只提示用户手动删除。
- 中文语言包 `installer/ChineseSimplified.isl` 是 Inno Setup 的非官方翻译，取自 6.7.3。升级 CI 里的 Inno Setup 版本时要一起更新。
- 安装包没有代码签名。从浏览器下载后第一次运行会出现 SmartScreen 提示，公司的安全软件也可能拦截。之后的自动更新不经过浏览器，一般不会再出现这个提示。
- `PresenceHubTests` 的几个用例（屏蔽、改名通知、离线和退出）在整套测试并行运行时偶尔失败，单独运行稳定。原因是用 LongPolling 收消息时，等待某条消息的时机受机器负载影响。CI 上遇到时先重跑。

## 界面

- **旧版客户端看不到 Server 的错误说明**：Server 改为只返回错误码后，0.1.2-dev.26 及更早的客户端遇到接口错误时只显示「请求失败（HTTP 状态码）」，更新客户端后恢复。
- 内置规则库的英文名称按默认名称（中文）在接收方本机翻译。本机缓存的规则库还没有这个名称（第一次启动、规则库刚新增），或者名称来自个人分类、应用自己的产品名时，英文界面里仍显示原名。
- 服务器地址不在界面上显示，但仍以明文写在 `%APPDATA%\DeskPal\settings.json` 和客户端程序里，只是不让普通用户看到，不能当作保密手段。
- 没有 WebView2 Runtime 的系统上还没有实测安装（Velopack 会先装运行时）。启动时检测到缺少只能提示下载，面板和登录页打不开。
- 前端的模拟宿主（`mockHost`）也打进了发布包。它只在没有 `chrome.webview` 时动态加载，客户端里不会执行。加上使用统计和应用详情的样例后约 440 KB（gzip 后约 33 KB）。
- 页面里的时间（“已持续 12 分钟”）由宿主每 30 秒重新推送一次，不是页面自己计时。只有「n 秒后变为」的倒计时由页面每 250 毫秒自己刷新，宿主每次推送时重新对时。
- 标题栏拖动依赖 WebView2 的非客户区支持（`IsNonClientRegionSupportEnabled`）。WebView2 Runtime 太旧时标题栏拖不动，最小化和关闭按钮仍可用；Runtime 会随 Edge 自动更新，一般不会遇到。
- 窗口在 Windows 10 上没有圆角（DWM 圆角只在 Windows 11 生效），仍有边框和阴影。暂不处理：WebView2 是单独的子窗口，WPF 透明窗口裁不到它；`SetWindowRgn` 裁出的圆角有锯齿，还会去掉 DWM 阴影。
